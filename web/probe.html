流控（重要）：设备侧缓冲只有约 12 KB（vendor RX/TX FIFO 各 4 KB + 8 KB stream buffer）。 所以本页不做「先 transferOut(1MB) 再 transferIn」——那样设备 FIFO 一满就一直 NAK， transferOut 永不 resolve，直接死锁。正确做法是分块 ≤ 4 KB，且先挂上 IN 读、再发 OUT 形成流水线： const rd = transferIn(...); await transferOut(...); await rd;。

5 · 设备心跳（契约 §4 / §6.5）

设备空闲 ≥ 1 s 时会主动在 IN 上发 \nHB <uptime_ms>\n。心跳与回环数据共用同一条 IN 流， 因此回环校验必须先剥离 HB 行再逐字节比对（本页 §4 已强制过滤）。 首包可能是心跳也可能不是，本页不假设 IN 第一段就是回环数据。

怎么判断 MTP 与 WinUSB 各绑到哪个接口

看什么MTP 那一路Vendor 那一路
接口号（页面里读） 模式 B = IF0，class 0x06（Still Image/PTP），alternate 里有 interrupt 事件端点 + bulk 数据端点 模式 B = IF1（模式 A = IF0），class 0xFF（vendor-specific），bulk IN/OUT 同号（0x03/0x83）
设备管理器拓扑 顶点为 MeidaP4 Probe（复合父设备，usbccgp）→ 子节点 便携设备 里出现 MeidaP4 Storage 同一父设备下的另一个子节点，类别 通用串行总线设备，名字含 WebUSB/WinUSB
实例 ID 的 &MI_xx USB\VID_303A&PID_4002&MI_00 → MI_00 = 接口 0 = MTP USB\VID_303A&PID_4002&MI_01 → MI_01 = 接口 1 = Vendor（模式 A 无 MI 或 MI_00）
驱动程序文件 属性→驱动程序→驱动程序文件里出现 wpdmtp.sys（WPD 走 UMDF，服务名一般是 WUDFRd） 属性→驱动程序→驱动程序文件里出现 winusb.sys，服务名 WINUSB

一行 PowerShell 看全（判据以 Service 为准，模式 B 应为 WUDFRd / WINUSB 两行）：
Get-PnpDevice -PresentOnly | ? InstanceId -like 'USB\VID_303A*' | select Status,Class,FriendlyName,InstanceId | ft -Auto
Get-PnpDevice -PresentOnly | ? InstanceId -like 'USB\VID_303A*' | % { $_.InstanceId; (Get-PnpDeviceProperty -InstanceId $_.InstanceId -KeyName DEVPKEY_Device_Service).Data }
完整步骤与失败判读见 docs/host-verify.md §8。
